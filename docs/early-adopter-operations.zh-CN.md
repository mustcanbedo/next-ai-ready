# next-ai-ready 早期采用执行记录

> 建立日期：2026-08-26  
> 目标：把“有人看过”与“真实项目成功采用”分开记录，为 `0.1.0` GA 提供证据。

## 1. 成功定义

一次仓库外成功安装必须同时满足：

1. 项目不属于 `mustcanbedo/next-ai-ready` 仓库、fixture 或维护者临时测试仓库。
2. 使用公开 npm 包完成 `install -> init -> build -> doctor`。
3. `doctor` 没有 error；warning 已被理解并记录，不得通过删除检查伪造通过。
4. 有公开仓库、公开部署，或采用者授权提供的脱敏构建证据。
5. 记录首次成功耗时、失败步骤和 Next.js/包管理器/内容来源。

公开生产案例还必须具有可访问 URL，并至少验证一个 HTML 页面和一个 AI 入口。七日留存需要
采用者在七天后确认仍保留集成，或提供新的构建/部署证据。

## 2. 阶段与退出条件

| 阶段 | 含义 | 退出条件 |
|---|---|---|
| `identified` | 找到与项目明确相关的公开 Next.js 项目 | 已确认框架、公开项目和具体适用场景 |
| `invited` | 已发送一次个性化、允许拒绝的邀请 | 记录公开渠道和日期，不自动追发 |
| `engaged` | 维护者明确回复或创建 adopter issue | 对方提出问题或同意尝试 |
| `installing` | 正在真实项目中执行接入 | 已记录开始时间和当前步骤 |
| `verified` | 满足仓库外成功安装定义 | 有脱敏证据和结果记录 |
| `deployed` | 已形成公开生产案例 | URL 与 AI 入口均通过验证 |
| `retained-7d` | 七日后仍在使用 | 有回访或构建证据 |
| `closed` | 拒绝、不适配或无后续 | 记录原因，不继续打扰 |

没有回复不能记为“有效交流”。同一维护者只发送一次初始邀请；除非对方已经回复，否则不做
自动跟进。优先使用项目公开的 GitHub Discussion、Issue 模板或维护者明确提供的公开渠道。

同一个阻塞在至少两个独立项目出现后，才进入 SDK 优先级评审。单个项目的特殊需求优先通过
文档、recipe 或 adapter 解决，不直接扩大核心 API。

## 6. 每周复盘

每周只回答五个问题：

1. 本周新增了多少个 `engaged`、`verified`、`deployed` 和 `retained-7d`？
2. 哪一步的流失最多，是否能在十分钟快速路径内复现？
3. 是否有两个独立项目遇到同一阻塞？
4. 哪个公开渠道产生了真实访问、问题或安装，而不仅是展示量？
5. 下周只修哪一个最大共同阻塞，并停止哪一个无效渠道？

渠道发布和 24 小时/7 天结果记录在 [`distribution/results.md`](./distribution/results.md)。
