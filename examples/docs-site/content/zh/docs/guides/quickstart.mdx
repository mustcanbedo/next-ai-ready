# 快速开始

本指南按约 10 分钟的基础接入流程组织，目标是验证知识平面端点能返回真实内容。依赖下载和生产构建可能需要更长时间，具体取决于网络和项目情况。

## 前置要求

- Node.js 20 或更高版本。
- Next.js 14.2+，使用 App Router。
- npm；已有 pnpm 项目继续使用 pnpm。

## 1. 创建项目

**新项目：**

```bash
npm create next-ai-ready@latest my-site
cd my-site
npm install
npx next-ai-ready init
```

脚手架会提供可运行的最小 App Router TypeScript 应用和初始 MDX 内容，但不会预生成 AI-ready 配置或 handler；安装后显式执行 `init` 才会添加这些接线。

**已有 Next.js App Router 项目：**

在现有项目根目录执行，不需要重新创建应用：

```bash
pnpm add next-ai-ready
pnpm exec next-ai-ready init
```

`init` 默认只接入知识平面（Knowledge-only）：生成配置、知识平面路由，并接好 `next.config` 与构建脚本。它不会默认启用 OpenAPI、MCP 或 Actions；这些不属于本次基础验收。

## 2. 添加内容

在项目根目录创建 `content/docs/quickstart.mdx`，保存以下内容：

```markdown
---
title: 快速接入检查
summary: 安装项目依赖并验证逐页 Markdown 输出。
---

# 快速接入检查

在项目根目录运行 `pnpm install` 安装依赖。
```

这个文件匹配 `init` 默认的 `content/**/*.{md,mdx}` glob，并映射到 `/docs/quickstart.md`。在 `content/` 下保存源文件不会创建浏览器 HTML 页面；网页仍由原有 Next.js 页面或 MDX 渲染流程提供。

### 修改站点配置

编辑已有的 `ai-ready.config.ts` 或 `ai-ready.config.mjs`，不要另建第二个配置。将 `site.name`、`site.description` 改为实际站点信息，`site.baseUrl` 改为真实生产域名，不要保留示例域名或填写 localhost。

下面展示默认配置结构；`https://docs.example.com` 只是占位，必须替换：

```js
import { defineConfig } from "next-ai-ready";

export default defineConfig({
  site: {
    name: "你的站点名称",
    baseUrl: "https://docs.example.com",
    description: "描述站点实际提供的内容。",
  },
  content: [
    "app/**/*.{md,mdx}",
    "content/**/*.{md,mdx}",
    "src/app/**/*.{md,mdx}",
    "src/content/**/*.{md,mdx}",
  ],
});
```

默认 glob 已能覆盖本例，无需为此修改。已有项目应保留或按真实内容目录调整 glob；若已有 Content Source Adapter，继续使用实际的数据源与路由映射，不要用示例配置覆盖。

## 3. 构建与检查

```bash
npx next-ai-ready build
npx next-ai-ready doctor --score
```

已有 pnpm 项目对应使用 `pnpm exec next-ai-ready build` 和 `pnpm exec next-ai-ready doctor --score`。

构建会扫描内容并写入 `public/` 与 `.next-ai-ready/`。生成文件和路由数量取决于实际内容与配置，不应按固定数量判断成功。

`doctor` 应报告 **0 个错误**。逐条理解 warning 和 **Top fixes**，确认哪些需要修复、哪些暂时接受；没有错误不代表所有 warning 都已解决，也不能代替 HTTP 验证。

纯知识平面缺少 OpenAPI 的误报修复已随 alpha.22 发布；已安装 alpha.21 的用户请升级。
OpenAPI 仍是可选能力，不要仅为消除此告警启用能力平面。

## 4. 验证公开端点

构建应用并启动生产服务器：

```bash
npm run build
npm run start
```

已有 pnpm 项目使用 `pnpm run build` 和 `pnpm run start`。`init` 会在缺失时将 `next-ai-ready build` 接入应用构建脚本，确保应用构建前更新知识平面产物。

在另一个终端执行：

```bash
curl -i http://localhost:3000/llms.txt
curl -i http://localhost:3000/docs/quickstart.md
curl -i -H 'Accept: text/html' http://localhost:3000/
```

检查响应头与正文：

- `/llms.txt` 返回 `200`，索引包含“快速接入检查”及生产域名下的正确页面链接。
- `/docs/quickstart.md` 返回 `200`、`Content-Type: text/markdown`，正文包含“快速接入检查”和 `pnpm install`，而不是 `not_found` 恢复文档。仅有 `200` 不足以说明找到了内容。
- 普通首页 `/` 仍返回原有 HTML，`Content-Type` 为 `text/html`。接入不会替换原有浏览器页面。

还可检查 `/llms-full.txt` 是否包含完整内容。部署后，应在真实生产域名下重复检查端点及链接。

若响应不符合预期，按以下方向排查：

- **缺少内容或出现 `not_found`：** 确认 `content/docs/quickstart.mdx` 已保存、被 glob 或 adapter 读取，并已重新构建；检查 `.next-ai-ready/graph.json` 是否包含 `/docs/quickstart`。
- **路由返回 404 或 HTML：** 检查 `init` 生成的 handler、`withAiReady({ agentReadable: true })` 接线，以及源文件到路由的映射。不要把 `app/%5Fai-ready/` 改名为 `app/_ai-ready/`。
- **索引或 canonical 链接使用错误域名：** 修正现有配置的 `site.baseUrl`，重新构建并重启生产服务器。
